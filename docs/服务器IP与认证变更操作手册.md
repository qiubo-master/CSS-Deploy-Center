# ForgeOps 服务器 IP、密码与 SSH Key 变更操作手册

## 一、先判断哪些内容需要修改

| 发生的变化 | 中台服务器编辑框 | GitHub 仓库连接 | GitHub Actions Secrets |
|---|---|---|---|
| 只有公网 IP 变化 | 修改“公网 IP / 主机名”，重新取得“SSH 主机指纹” | 不用修改 | 修改 `DEPLOY_HOST` 和 `DEPLOY_HOST_KEY` |
| 只有 SSH 密码变化 | 选择密码认证并填写新密码；其他字段不动 | 不用修改 | 使用 SSH Key 发布时不用修改；工作流直接使用密码时需同步更新对应 Secret |
| SSH 端口变化 | 修改 SSH 端口并重新取得主机指纹 | 不用修改 | 修改 `DEPLOY_PORT` 和 `DEPLOY_HOST_KEY` |
| SSH 用户变化 | 修改 SSH 用户 | 不用修改 | 修改 `DEPLOY_USER` |
| 部署 SSH Key 变化 | 粘贴新私钥，并把对应公钥加入服务器 `authorized_keys` | 不用修改 | 修改 `DEPLOY_SSH_KEY` |
| GitHub 仓库改名或迁移 | 服务器信息不用修改 | 在项目接入中修改仓库地址 | 新仓库重新配置全部生产 Secrets |

结论：GitHub 仓库地址属于项目，不属于服务器。服务器 IP 或密码变化，不会改变 GitHub 仓库连接。但 GitHub Actions 要连接服务器，因此 IP、端口、用户、主机指纹或部署 Key 变化时，必须同步更新对应的部署 Secret。

## 二、进入服务器编辑框

1. 打开 CI/CD 控制台。
2. 点击左侧“资源接入”。
3. 在“已接入服务器”中找到目标服务器。
4. 点击“编辑服务器”。
5. 核对服务器 ID，编辑时服务器 ID 不允许改变。

## 三、各字段如何取得

### 公网 IP / 主机名

- 阿里云：进入 ECS 实例详情，复制“公网 IPv4 地址”。
- AutoDL：复制平台提供的 SSH 命令，取 `用户@` 后、`-p` 前的主机名或 IP。
- IP 变化时只修改这一字段，不需要重新建立项目或流水线。

### SSH 端口

- SSH 命令包含 `-p 51009` 时，端口就是 `51009`。
- 未显示 `-p` 时通常是 `22`。
- 端口变化后必须重新获取 SSH 主机指纹。

### SSH 用户

- 取 SSH 命令中 `@` 前面的值，例如 `root@host` 的用户为 `root`。
- 阿里云镜像也可能使用 `ubuntu` 或 `ecs-user`。

### 密码或 SSH 私钥

- 密码来自云平台的密码重置功能或 AutoDL 实例连接信息。
- 私钥必须与服务器 `~/.ssh/authorized_keys` 中的公钥配对。
- 编辑服务器时，密码和私钥留空表示继续使用原凭据；填写新值才会覆盖。
- 中台不会把已保存密码或私钥回显到页面。

### SSH 主机指纹

在可信电脑执行：

```powershell
ssh-keyscan -T 10 -p SSH端口 -t ed25519,rsa 服务器IP或主机名
```

复制输出中以主机名或 IP 开头的完整公钥行。不要在未核对服务器身份时盲目接受新指纹。

### 监控接口与监控令牌

- 监控接口由 ForgeOps 资源代理提供，通常以 `/v1/resources` 结尾。
- 监控令牌是安装代理时生成的只读 Bearer Token。
- 如果服务器 IP 变化导致监控地址不可达，应同时更新监控接口或重新建立 SSH 隧道。

### 部署根目录

- 普通云服务器推荐 `/opt/forgeops`。
- AutoDL 推荐使用数据盘目录，例如 `/root/autodl-tmp`。
- 已运行项目不要随意修改，否则新版本与旧版本可能进入不同目录。

## 四、更新 GitHub Actions Secrets

打开对应项目仓库：`Settings → Secrets and variables → Actions`，更新：

- `DEPLOY_HOST`：新公网 IP 或主机名。
- `DEPLOY_PORT`：新 SSH 端口。
- `DEPLOY_USER`：SSH 登录用户。
- `DEPLOY_HOST_KEY`：新地址和端口对应的主机公钥行。
- `DEPLOY_SSH_KEY`：只有部署私钥变化时才更新。

项目仓库地址、代码分支和流水线文件没有变化时，不需要修改 GitHub 连接，也不需要重新创建流水线。

## 五、项目绑定

服务器编辑框会列出所有项目及其 GitHub 地址。勾选表示该项目允许部署到这台服务器。取消勾选不会删除 GitHub 仓库，也不会删除服务器上的现有数据，只会阻止中台继续向该服务器下发该项目。

## 六、保存后的验证顺序

1. 保存服务器修改。
2. 回到项目看板，确认服务器从“离线/待接入”变为“在线”。
3. 检查 CPU、内存、磁盘和项目资源占用是否出现。
4. 在对应 GitHub 仓库同步更新必要的 Secrets。
5. 先执行一次健康检查或普通发布。
6. 在流水线列表确认“配置 SSH、上传版本、启动服务、健康检查”全部成功。
7. 用业务访问地址验证页面和接口。

## 七、常见场景

### 阿里云只换 IP，密码不变

编辑服务器的公网 IP，重新取得主机指纹；GitHub 更新 `DEPLOY_HOST` 和 `DEPLOY_HOST_KEY`。密码、仓库地址、项目绑定和 `DEPLOY_SSH_KEY` 均不用动。

### AutoDL 重建实例，IP、端口和密码都变化

编辑地址、端口、用户和密码，重新取得主机指纹；重新确认监控隧道与部署目录；GitHub 更新 `DEPLOY_HOST`、`DEPLOY_PORT`、`DEPLOY_USER`、`DEPLOY_HOST_KEY`。如果仍使用原部署 Key 且公钥已加入新实例，则 `DEPLOY_SSH_KEY` 不变；否则需要重新配置 Key。

### 保存后仍显示离线

依次检查实例是否开机、安全组、SSH 地址与端口、监控代理、监控令牌和隧道。服务器能 SSH 登录但看板离线，通常是监控接口或隧道问题，不是 GitHub 仓库问题。
